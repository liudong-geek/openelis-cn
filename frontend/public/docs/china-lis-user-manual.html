适用对象：申请与标本接收人员、检验技师、结果审核人员、报告发布人员、质量负责人、系统管理员和审计人员

本手册适用于当前本地部署版本。系统依据岗位权限展示菜单和业务操作。HIS/EMR 接口、仪器连接、报告样式、标签规格、危急值及质控规则按照医院正式资料配置并验收。

1. LIS 业务流程

LIS 以检验申请为业务起点，依次管理标本、检验任务、结果审核和报告发布。一份申请支持单管标本或按标本类型拆分的多管标本。

HIS/电子申请 ─┐
              ├→ 申请登记 → 生成申请号与管码 → 采集/签收 → 逐管验收
LIS 手工申请 ─┘                                      │
                                  合格管 → 结果录入 → 结果审核 → 报告发布/查询/打印
                                  拒收管 → 记录原因 → 关联补采 ────────────┘

核心业务对象如下：

  • 申请号：一份检验申请的唯一标识。一份申请支持多个检验项目和多支标本管。
  • 管码：一支实际标本管的唯一标识。多管申请中的每支管具有独立管码。
  • 检验任务：申请项目与标本管形成的待检验记录。已验收合格的标本管进入检验环节。
  • 逐管验收：同一申请内的标本管分别验收。合格管继续检验，拒收管进入补采流程。

各业务环节以系统状态为流转依据。操作完成后，系统状态应更新为下一业务阶段。“保存结果未知”状态下，操作人员通过查询功能核对服务器记录，禁止重复提交。

2. 首次使用流程

培训环境使用明确标记的测试患者和测试标本。正式联调前，测试数据不包含真实患者资料。

  1. 操作人员登录系统并核对右上角账号信息和岗位权限。
  2. 操作人员进入“工作台”，查看待接收、待录入、待审核和待打印任务。
  3. 操作人员进入“申请与标本 → 申请列表 → 新建申请”，选择测试患者、送检机构、标本类型和检验项目并保存申请。
  4. 操作人员在申请流程中核对管码、登记采集信息并预览标签。演示环境支持“仅采集，稍后签收”。
  5. 操作人员进入“申请与标本 → 标本处理”，扫描管码并完成签收和验收。
  6. 检验技师进入“检验 → 待录入结果”，填写并保存检验结果。
  7. 结果审核员进入“审核与报告 → 审核工作台”，完成结果通过或退回。
  8. 报告人员进入“审核与报告 → 患者检验报告”，查询已审核结果并预览报告。

标本验收后未形成待录入任务时，核查范围包括管码、验收状态、项目专业组和当前账号专业组权限。

5. 申请与标本操作规程

5.1 申请接收与手工建单

  • 电子申请：系统在“待接收电子申请”中展示 HIS/EMR 传入的患者、项目、送检科室和医生信息。接收人员核对后完成接收。
  • LIS 手工申请：系统在“申请列表 → 新建申请”中提供手工建单功能，适用于单机运行、模拟演示或医院允许的补录场景。
  • 批量申请录入：系统提供同批申请录入功能，适用于体检或批量标本。正式使用以医院批量编号和标签规则为准。

手工建单程序如下：

  1. 接收人员检索并选择已有患者。系统无对应档案时建立患者档案。
  2. 接收人员核对姓名、性别、出生日期、证件或患者唯一编号。
  3. 接收人员选择送检机构、科室或病区、申请医生和优先级。
  4. 接收人员选择标本类型、组合项目或单项检验。
  5. 接收人员核对系统分配的标本管，保存申请并记录申请号。

系统在申请首次保存时生成申请号。外部系统已分配编号的申请使用外部编号字段。

5.2 单管与多管申请

单管申请中的检验项目由同一支标本完成。多管申请因标本类型、容器或检验要求不同，由两支或多支实际标本管完成。

系统按照“标本类型—检验项目”配置拆分标本管。血清生化和全血血常规位于同一申请时，系统分别形成血清管和全血管，并分配独立管码。

申请保存前的核对项目包括：

  • 检验项目与标本类型的关联关系；
  • 申请项目对应的标本管数量；
  • 每支管的条码、标本类型和检验项目；
  • 采集、签收、验收和拒收操作对应的标本管。

5.3 标本采集与标签

  1. 采集人员打开申请并进入采集步骤。
  2. 采集人员逐管核对患者、标本类型、管码和检验项目。
  3. 采集人员登记采集时间和人员。暂未签收的标本使用“仅采集，稍后签收”。
  4. 采集人员预览标签并核对患者标识、管码、标本类型和条码。
  5. 标签打印完成后粘贴至对应容器，标签位置保留液面和原有关键标识。

标签打印异常的核查范围包括浏览器打印窗口、打印机、纸张和标签预设。打印状态未确认期间禁止重复打印。

5.4 扫码签收与逐管验收

操作入口：申请与标本 → 标本处理。

  1. 接收人员扫描或输入管码，系统显示对应申请、患者和标本管。
  2. 接收人员核对患者身份、标本类型、容器、采集时间和检验项目。
  3. 未签收标本完成签收登记。
  4. 合格标本完成验收并进入结果录入队列。
  5. 不合格标本选择拒收原因并提交，系统保存拒收记录。
  6. 需要重新采集的标本建立关联补采申请，补采标本使用新管码。

同一申请中的标本管独立处理。单管拒收不撤销同一申请中的其他合格管。已验收合格管的检验项目继续流转。

5.5 标本异常

标本量不足、容器错误、凝块、溶血、污染和身份不清等拒收原因按照医院制度配置。系统提供拒收原因、处置记录和补采关联功能。强制拒收和让步接收条件由医院制度确定。

6. 检验操作规程

6.1 结果录入

操作入口：检验 → 待录入结果。

  1. 系统默认加载当前账号权限范围内的待处理队列。筛选条件包括实验室编号、专业组、日期和状态。
  2. 检验技师选择标本并核对患者、管码和检验项目。
  3. 检验技师逐项填写结果并核对单位、参考范围、异常标志和仪器原始值。
  4. 检验技师保存当前结果。保存成功状态表示结果录入完成，结果尚未审核和发布。
  5. 结果不可编辑时，检验技师通过“受限说明”核查标本验收、项目拒收、质控阻断和岗位权限。

页面顶部数量表示检验任务数，左侧数量表示标本记录数。加载失败或状态未知时，页面空白不表示任务数为零。

6.2 外送检验

外送检验页面默认展示患者和实验室编号查询。出生日期、性别等条件位于高级搜索。查询结果包含外送机构、检验项目、送出时间和回传结果。

外送检验正式启用的前置条件包括外送机构资料、项目映射、报告回传方式和责任边界。

6.3 检验工作单

检验工作单按照检验项目、组合项目、专业组或优先级对同一待检验任务集合进行分类筛选和打印。四种分类属于查询条件，不构成独立业务流程。

工作单打印前核对专业组、筛选条件、项目总数和异常标记。工作单用于台面作业，系统中的标本状态和结果记录仍为正式业务记录。

7. 审核与报告操作规程

7.1 结果审核

操作入口：审核与报告 → 审核工作台。

  1. 结果审核员按照专业组、申请单或检验日期加载待审核队列。
  2. 结果审核员核对患者、标本、结果、单位、参考范围、异常标志和历史结果。
  3. 符合要求的结果执行通过操作；需要修改的结果执行退回操作并填写退回原因。
  4. 批量通过操作在选中范围复核完成后提交。

审核统计覆盖本次查询的全部任务，不限定于当前分页。质控受阻、已签发遗留或权限不足的记录以只读状态显示。

结果审核员不修改原始结果。危急值、质控失控和身份不清记录按照医院制度完成处置。

7.2 报告查询、发布与打印

操作入口：审核与报告 → 患者检验报告。

  1. 报告人员按照实验室编号、患者、送检机构或日期查询检验记录。
  2. 报告人员选择已审核申请并核对报告分组和报告内容。
  3. 报告人员预览报告并核对患者、结果、单位和参考范围。
  4. 具备报告权限的人员执行报告发布或签发。
  5. 系统在打印时登记打印记录。

报告预览不属于正式报告。报告样式、电子签章、审核层级、更正或作废流程和临床发送方式以医院资料和现场验收结果为准。报告更正和作废尚未完成生产闭环验收。

7.3 业务统计

检验工作量、项目汇总、外送结果、不符合项和审核超时统计采用统一分类查询。用户选择统计类型并设置专业组、优先级和日期条件。正式统计口径由医院确认。

8. 质量管理

8.1 不符合项

不符合项用于记录标本拒收、申请错误、结果问题和流程偏差。页面默认展示台账列表和常用搜索条件，状态、类别和严重度位于高级搜索。

不符合项处理流程为：登记事件 → 分派或调查 → 纠正措施 → 复核关闭。记录内容包括发生时间、业务对象、原因、处理人员和处置证据。

8.2 质量预警

质量预警按照配置规则展示待处理风险。告警确认表示责任人员已接收信息，告警关闭表示处置完成且有效性验证通过。

仪器质控规则、危急值范围和放行条件属于医院制度。系统管理员维护配置，质量负责人执行处置和追踪。

9. 基础配置

基础配置按照业务领域分组，并通过左侧一级菜单进入。系统不使用顶部页签承担跨模块导航。

规则管理 反射检验、计算项目、参考范围、结果规则 主数据稳定后配置并验证

9.1 多管规则配置

  1. 系统管理员在“基础配置 → 检验主数据”中维护标本类型。
  2. 系统管理员为检验项目关联对应标本类型。
  3. 系统管理员核对组合项目中各子项目的标本类型。不同标本要求保持独立关联。
  4. 验证人员建立包含两种标本类型的测试申请，核对标本管数量和独立管码。
  5. 验证人员分别执行验收、拒收和补采，核对各标本管的任务隔离状态。

容器帽色、采血顺序、最小采血量、分杯和运输温度由医院提供正式规则。系统在规则确认后增加对应配置和验收场景。

10. 系统管理

10.1 用户与权限

系统账号按人员分配，禁止使用共享账号。管理员新增用户时应用默认岗位模板，选择专业组并核对职责边界。人员岗位变化、离职或轮岗时，管理员同步调整或停用账号。

10.2 操作日志

操作日志页面默认展示最近记录。日期、业务对象、操作类型、用户和业务编号位于高级搜索。审计查询按照日期范围和业务编号逐步缩小。日志导出限于授权审计用途。

10.3 系统参数与语言

系统参数、语言、翻译、日志级别、搜索索引和数据库维护由系统管理员操作。删除、停用和数据库清理等高风险操作显示确认框，执行前核对业务对象和影响范围。

11. 通用页面操作

11.1 查询

  • 列表页面默认展示当前权限范围内的数据和常用查询条件。
  • “高级搜索”包含日期、状态、类别和专业组等低频条件。
  • 查询无结果时，核查筛选条件、日期范围、业务状态、专业组和岗位权限。
  • 条码输入框支持扫描枪。扫描枪输入等同于键盘输入并提交回车键。

11.2 返回与未保存内容

详情页面使用“返回列表”返回原查询结果，系统保留搜索条件、筛选条件和页码。页面存在未保存内容时，操作人员完成保存或明确放弃后离开。刷新操作不用于判断保存结果。

11.3 弹窗

弹窗用于患者选择、详情查看、拒收原因填写和删除确认等短操作。申请、配置和多步骤业务使用完整页面。

危险操作弹窗显示操作对象、影响范围和红色确认按钮。关闭或取消弹窗不执行操作。

11.4 页面加载失败

页面加载失败后执行一次“重新加载页面”。再次失败时，操作人员记录页面名称、发生时间、申请号或管码和操作步骤，由系统管理员核查服务状态。写操作失败期间禁止重复提交。

12. 异常处置

12.1 菜单不可见

核查内容包括账号岗位、适用专业组和菜单权限。管理员修改权限后，用户重新登录系统。岗位模板包含菜单但后端拒绝操作时，管理员核查角色保存结果。

12.2 新建申请无可选标本类型或项目

核查内容包括检验项目启用状态、标本类型关联、专业组关联和送检机构开单范围。系统管理员完成主数据维护后，操作人员重新进入申请页面。

12.3 多管部分拒收

各标本管分别处置。合格管验收后继续检验，不合格管记录拒收原因并建立关联补采。整份申请保持有效，补采标本使用新管码。

12.4 扫描管码无响应

操作人员确认管码输入框处于焦点状态，并核查扫描枪回车设置。手工输入同一管码可用于区分设备问题和业务数据问题。标签内容应与系统管码一致。

12.5 保存状态未知

操作人员保留当前页面并查询服务器记录。状态确认前禁止执行保存、审核、发布、打印和接口重发。

12.6 结果无法录入、审核或发布

核查顺序为标本验收状态、项目拒收状态、专业组权限、结果保存状态、质控阻断状态和审核状态。页面“受限说明”显示当前限制原因。

12.7 打印内容或尺寸异常

核查内容包括标签或报告预设、浏览器缩放、纸张规格和打印机设置。校准使用测试标签和测试报告，患者正式标签不用于反复试印。

13.1 申请与标本接收人员

  • 待接收电子申请、采集、签收和验收待办已处理。
  • 拒收、补采和身份不符记录已处理。
  • 当日未完成申请和未处理标本管已核对。

  • 本专业组待录入结果和退回结果已处理。
  • 仪器导入失败、受限任务和未保存输入已核查。
  • 急诊任务和超时任务已在交班前确认。

13.3 审核与报告人员

  • 待审核和退回队列已处理。
  • 异常结果、质控阻断和危急值处置已核对。
  • 待发布、待打印和报告异常已核查。

  • 质量预警和不符合项已查看。
  • 纠正措施和未关闭事件已追踪。

13.5 系统与账号管理员

  • 接口失败、服务异常和发送积压已核查。
  • 账号、权限和主数据变更已处理。
