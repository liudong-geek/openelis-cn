# Q02 质控操作与审核放行约束验收记录

日期：2026-09-17

## 本批范围

本批把已有室内质控失控记录接入结果审核放行链路。医院仪器清单、正式质控规则和岗位 SOP 尚未提供，因此验证使用合成的分析仪、项目、质控结果与纠正措施，不写入真实临床或设备数据。

## 已实现行为

- 仪器结果按“分析仪 + 检验项目”检查质控状态；存在 `REJECTION` 严重程度且状态为 `UNRESOLVED` 或 `ACKNOWLEDGED` 的失控记录时，禁止审核通过。
- `WARNING` 级失控不阻断；人工录入且未关联分析仪的结果不适用本门禁；结果退回始终可用。
- 审核查询返回服务端计算的只读阻断状态和失控证据，前端显示阻断提示、禁用该行“通过”，批量通过自动排除受阻结果。
- 后端在电子签名前、写入后以及事务提交前重新检查并锁定质控失控记录；伪造前端请求不能绕过门禁，受阻请求返回 HTTP 422。
- “确认已知悉”和“解决失控”分别保存确认人/时间与解决人/时间。仅确认不会恢复放行，必须填写纠正措施与验证结果并将记录解决。
- 解决操作要求非空纠正措施；重复解决返回既有完成状态，不重复改写首次确认或解决证据。
- 失控记录的触发质控结果、规则、时间、严重程度、分析仪和检验项目由数据库触发器冻结，状态流转不能改写门禁依据。
- 审核签名快照记录分析仪 ID，并标记质控门禁为 `PASSED` 或 `NOT_APPLICABLE`。
- 质控接口限制为结果、审核或管理员角色访问。

## 操作流程

1. 结果审核查询仪器结果；页面发现拒绝级未解决失控后显示“质控失控阻断结果放行”。
2. 操作人员仍可退回结果；“通过”保持禁用。
3. 在“质量与异常 → 室内质量控制 → 室内质控工作台 → 质控失控预警”找到已确认记录。
4. 点击“登记纠正措施”，填写校准、复测和质控恢复证据，提交“解决并恢复放行”。
5. 重新查询同一结果；服务端不再返回阻断证据，“通过”恢复可选，随后按原审核流程提交。

医院正式启用前需配置获批的 Westgard 规则、质控品批号、浓度水平、分析仪与项目映射，并由检验科确认哪些严重程度必须阻断放行。

## 验证结果

- Java 21：生产源码和测试源码编译通过。
- 后端无容器回归：9 个测试类、124 项通过，覆盖门禁范围、查询投影不可由客户端覆盖、签名前及提交前复核、确认与解决证据分离、纠正措施必填、状态重放及既有质控规则。
- 前端：4 个相关测试文件、24 项通过；Prettier 检查通过。
- 中文：候选区检查 1876 个、原项目检查 1881 个被引用文案 ID，均通过。
- PostgreSQL 14.24：迁移从 853 增至 855；阻断 1 条、确认后仍阻断、解决后阻断 0 条、证据字段不可改写、回滚后模拟数据零残留。
- 浏览器：真实审核页显示 1 个受影响结果且“通过”禁用；真实质控页要求填写纠正措施；解决后重新查询，同一结果“通过”恢复并完成模拟审核提交。
- 独立预览构建：1441 个模块通过。
- 正式前端构建：候选区 2656 个模块、原项目 2688 个模块通过。
- Java 21：候选区 WAR 构建通过，Jacoco 分析 2963 个类；原项目完整编译 2984 个生产源码和 705 个测试源码后，124 项无容器回归再次通过。

扩大回归另包含 30 项既有 Testcontainers 集成测试；本机没有 Docker，测试在启动 PostgreSQL 容器前终止，没有发生代码断言失败。本批使用独立 PostgreSQL 14.24 实例验证数据库迁移和约束，并在写回原项目后再次完成无容器测试与正式前端构建。
