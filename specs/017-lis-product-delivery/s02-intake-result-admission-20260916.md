# S02：主流程整合与当前逐管结果准入

本批以冻结的 S01 工作源为基线，仅在 `openelis-s02` 隔离候选中修改；不把 S01 既有增量重复计入本批。不使用医院资料、临床记录或原运行栈。无需新增表或迁移，087 编号未占用。

## 本批交付

1. 开单仍走单次原子入口。修复旧测试把已废弃的“先保存、普通查询、逐管补写”当作主流程的断言，使用真实页面、Provider 与传输适配器验证取号、原子提交、回执和独立 GET 核对。未知结果保持待确认，重入和核对不触发补写。
2. 当前申请详情新增逐管 `resultEntryAdmission`，与不可修改的首次接受／拒收记录分别返回。历史 `currentAcceptanceVerified=false` 保持原义，既有 QA 检查不成为接受证据。
3. 新投影直接复用结果工作台的 `ResultSpecimenAvailabilityService`，进一步调用现有 `ResultIntakeAdmission` 与结果状态策略，核对当前标本状态、接受证据、申请和患者绑定、成员、采集签收版本、审核／发布状态。
4. 当前接诊岗位不自动获得结果录入权。投影按真实 analysis 所属检验组的 Results 角色及 Results 项目权限取交集。接诊用户可以读历史，但没有结果岗位权限时会显示阻断原因。
5. 实际逐管详情展示当前可录入／部分可录入／阻断／未核实及逐项原因。只在有允许项目且当前查询仍有效、无草稿或未知操作时显示可用的结果入口；点击时再次校验，保留完整申请号进入既有路由。结果页及保存服务继续重核状态与权限。

## 实现边界

- 读取沿用已授权的申请当前详情接口，在同一只读 REPEATABLE READ 事务中使用已载入的实际 analysis 和绑定的操作人；列表 S01 历史统计不附加逐项结果查询。
- 投影返回 sample、实管与 analysis 的身份和版本；成员重复／缺失、所有权或版本不符时返回 UNAVAILABLE。前端严格验证全量成员、版本和状态／原因一致性，损坏或陈旧的“READY”不开放入口。
- 该投影是当前事实说明，不是写入令牌，不写接受记录、不更新结果、不覆盖历史、不回填未知提交。
- 导航守卫覆盖本组件选择／预览、草稿、提交及所有未知操作凭证。现有 Provider 不公开兄弟组件尚未发送的预览状态，因此本批不宣称覆盖整页所有未发送预览。
- 无新依赖、数据库迁移、环境配置、真实设备、HIS 调用或部署变更。
