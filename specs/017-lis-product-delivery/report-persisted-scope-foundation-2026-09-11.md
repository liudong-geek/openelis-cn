# M1-A3：持久报告归属的模型前置

日期：2026-09-11 03:12（北京时间）。状态：模型前置的限定回归与独立审查通过；未接持久解析、未部署。承接 A1/A2，不重复身份授权实现，不代表 M1-A、M1-B 或报告 P0 完成。

## 本批问题与范围

当前 `PatientReportRelease` 及 058 迁移只有患者级版本、患者级活动草稿约束，没有可供服务端读取的完整报告组。不能把实时患者/申请汇总或客户端项目列表当成持久组。

本批是 M1-A 解析器所依赖的 M1-B 共享模型前置：新增唯一的 `ReportDocument` 归属及当前成员关系，准备未注册的增量迁移草案，实际构建无数据库 Hibernate SessionFactory 核对映射。**不新增发行表，不改旧发行链、058、报告号码或签名，不实现不可验证的 DAO/服务空壳。**

设计边界：

- 稳定归属唯一键为申请 ID＋组标识，规则版本只记来源，不另开一个平行报告身份。
- 当前组成员逐项关联 Analysis；不添加 Analysis 全局唯一、单标本、单专业组等未经确认的业务限制。
- 当前成员不是某个发行版本的封存成员。之后仍须在现有 release 上绑定文档、源修订及规范化快照。
- 使用 `BaseObject.lastupdated` 的唯一继承版本字段，不再新增第二个 `@Version`；子成员变更不自动证明父文档版本推进，真实锁/事务方案留给后续验证。
- `groupRuleVersion` 在本模型中是创建组定义时的来源版本，不可原位更新。后续若允许变更成员/规则，必须先明确成员修订及其规则来源，不能沿用旧来源版本冒充新规则；本批没有开放成员修改接口。
- 旧患者级报告表和所有约束原样保留。本批不关闭旧写旁路或报告 P0。
- 无新增 DAO/服务/HTTP 写入口；未注册迁移不代表 JPA 一定不会自动发现实体，因此本批禁止部署。

## 预先约定的检查

1. 实际构建 SessionFactory（禁止连接数据库、禁止 schema 自动生成），验证文档、成员及既有发行实体能够共同映射。
2. 核对实体主键、申请/患者 ID 类型、稳定组唯一性、成员唯一性、排序和外键映射；不能只 assertNotNull。
3. 验证继承版本字段唯一、成员无级联删除/孤儿删除、未加入跨组全局 Analysis 唯一约束。
4. 核对 XML 草案与映射字段和唯一键一致，且不修改旧表、不注册启动链。静态/无连接校验不冒充数据库迁移成功。
5. 保留实际红绿轮、源码/依赖指纹及独立审查；已有 A1/A2 不因此视为接通真实入口。
