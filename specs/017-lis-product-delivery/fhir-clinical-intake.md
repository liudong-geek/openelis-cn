# LIS 外部接口接入：本地试点契约与验收记录

本轮目标是让外部数据进入 LIS 正式业务模型，而不是仅保存在独立 FHIR 服务或模拟网关中。当前没有真实 HIS、仪器接口文档、测试地址和授权账号；下述接入只用于本地模拟验收，不代表完成医院联调或临床上线验收。

## 数据责任

| 数据 | 来源与接入对象 | 必须满足的条件 |
| --- | --- | --- |
| 医院、科室 | HIS 主数据，经映射发送 Organization | 唯一机构编码、既有机构类型、科室 partOf 指向医院 |
| 患者 | HIS/MPI，经映射发送 Patient | 唯一患者编号、身份信息完整，不凭姓名合并 |
| 检验目录、标本类型、单位 | LIS 受控配置，与 HIS/设备建立映射 | 已启用、编码唯一、项目适用于标本、结果配置完整 |
| 检验申请 | ServiceRequest | 患者和送检机构已存在，来源系统＋申请号唯一 |
| 仪器结果 | Observation | 申请、患者、标本、项目及单位全部一致；已采集签收 |
| 已审核报告 | DiagnosticReport / 现有报告模块 | 经 LIS 审核；设备 final 不等于 LIS 审核通过 |

不从不明网络来源补造医院、科室、医生或参考范围。目录映射不完整时拒绝报文；不自动选择同名项目，不把单位不符的结果直接入库。

## 接口地址及权限

本地地址：`http://127.0.0.1:18080/api/OpenELIS-Global/fhir`。

- `/metadata`：FHIR 能力声明。
- `PUT /Organization/{UUID}`：创建或更新主数据；系统管理权限。使用稳定 UUID 重试，不生成重复机构。
- `GET /Organization/{UUID}`：从 LIS 数据库回读，含 `partOf`。
- `POST /Patient`、`GET /Patient/{UUID}`：建档与回读；建档需登记权限。患者编号重复返回 409，须引用既有档案，不自动覆盖人口学资料。
- `POST /ServiceRequest`：接收一项待采检验申请；登记权限。首次 201、同报文重发 200、同标识不同报文 409。
- `GET /ServiceRequest/{UUID}`：标本采集前从接收记录读取，采集后关联检验任务。
- `POST /Observation`：定量结果接收；检验结果录入权限及检验组范围。不得直接完成审核。
- `GET /Observation/{UUID}`、`GET /DiagnosticReport/{申请UUID}`：回读结果与报告；正式状态须来自 LIS 人工审核。
- `DELETE /Observation/{UUID}`：返回 405，不能通过设备接口删除结果。
- 目录管理接口 `GET /rest/test-catalog/tests/{testId}/basic-info` 增加只读 `testGuid`，供接口映射使用，客户端不能借此改写主键。

本地测试沿用账号认证，不开放匿名接入，不创建默认“接口超级管理员”。真实部署需配置独立账号、来源权限、TLS、审计和网络访问控制。本地 HTTP 只用于明确标记的模拟数据。

## 本轮支持的申请范围

本轮受限试点中，一个 ServiceRequest 对应一个已启用的单一主结果定量项目和一项待采标本申请。按当前结果组件模型检查，不使用旧 `test_analyte` 表是否存在来猜测新目录是否配置完成。项目与主结果的单位必须一致，不能把多组件检验压缩成一个结果。包含：

- `identifier`：恰好一组 `system` 与 `value`。来源命名空间不可省略；不同来源可有相同业务号。
- `status=active`、`intent=order`，不得带 `doNotPerform=true`。
- `subject.reference=Patient/{已同步UUID}`。
- `requester.reference=Organization/{医院或科室UUID}`；科室会校验医院归属。
- `code.coding`：一个 `http://loinc.org` 编码，或 `{oe.fhir.system}/test-guid` 对应 LIS 项目 GUID。
- `specimen.reference=#requested-specimen`，并在 `contained` 中携带该 Specimen；其 `type.coding.system={oe.fhir.system}/sampleType`、`code` 对应既有标本类型缩写。
- 入口不接受伪造的采集时间或签收时间。申请与 `sample_type_request` 在同一事务生成；临床人员后续完成采集、签收、验收。
- `authoredOn` 可省略，申请日期由服务端补齐；提供时不接受未来日期。采集后回读仍保留来源申请号、项目编码及送检科室，标本引用切换为实际标本 UUID。

接收记录保存来源系统、外部号、原始 FHIR 请求、摘要、LIS 申请关联和操作者。数据库唯一约束与事务级锁防止并发重发重复建单；中途失败回滚申请及待采任务。流水号可能存在合理空号，不要求连续无缺号。

### 结果接收边界

当前试点按单项目定量结果验收：明确数值、明确单位、明确申请/标本/患者引用。申请和结果可使用同一 LOINC 或 `{oe.fhir.system}/test-guid` 编码；结果必须与被引用申请的项目一致，不能用同编码查询到的第一条目录记录替换项目。比较符结果、复杂定性字典、多组分面板、微生物、病理及厂家原始报文需另行适配，不应当作已经支持。重复结果须核对既有结果或走更正流程。

结果小数位及结果组件必须从受控项目配置传递到保存、审核和报告。缺少精度配置或数值超过已配置小数位时返回 422，不静默截断或舍入。没有标准术语映射的项目回读使用 LIS 稳定 GUID，不省略项目编码，也不伪造 LOINC。

### 未在本轮宣称支持的范围

- 任意 FHIR transaction Bundle、HIS 自动轮询、任意医院私有协议或物理仪器直连。
- 同一申请多项目打包、HIS 撤单/退费/更正、医生及就诊 Encounter 的完整映射。
- 原接口的“给既有标本追加项目”创建语义已收紧；不能用新申请接口代替人工更正。
- 全量主数据交换目录、独立接口监控台、失败报文人工处理台。
- 仪器并发结果写入的原子去重、结果 PUT 更正的完整版本控制、所有旧接口的权限复核。本轮仅验证顺序重复结果拒绝；不得把申请并发去重的通过结论推广到结果并发写入。
- 重试前仍会重新校验当前主数据；若项目后来停用，旧申请重发可能返回 422，接入方应保留首次成功回执并按 UUID 回读。
- 独立 FHIR 存储的搜索/分页目前仍受本地 FHIR 存储是否启用影响。这里的写入和按 UUID 回读使用 LIS 库，不能据此宣称全套搜索能力已联通。

## 本地验证方法

构建：`Dockerfile.local-fhir-test`，依赖本地已有 Java 21 后端测试镜像。

API 验收：`scripts/qa/fhir-intake-smoke.mjs`，只允许 localhost 且须显式指定 `--write-synthetic`。通过环境变量提供 `LIS_API_USER`、`LIS_API_PASSWORD`，不在脚本内写入密码。可设置 `LIS_FHIR_SYSTEM`、`LIS_TEST_GUID` / `LIS_TEST_LOINC`、`LIS_SAMPLE_TYPE_CODE`。增加 `--main-flow` 执行采集、结果、审核与报告验收。

增加 `--save-report` 将本轮模拟 PDF 保存到 `tmp/pdfs/` 供内容检查。脚本的 `main-flow-passed` 指 API 数据链路与 PDF 文件响应通过，不表示中文报告视觉验收通过。

未指定项目映射时，脚本调用现有管理接口建立名称含“接口测试项目”、编码 `TEST-API-时间戳` 的独立数值项目，使用既有百分比单位，不配置或声称临床参考区间。默认测试标本类型 ID 4（全血）、检验组 ID 36 均须在接口返回的目录中存在；可通过 `LIS_TEST_SAMPLE_TYPE_ID`、`LIS_TEST_LAB_UNIT_ID` 指定已核对的配置。不会将种子项目错误地批量激活或随意补齐医学规则。

采集签收和人工审核部分使用当前页面同源的内部业务接口与真实会话，不绕过业务持久化层，也不直接改数据库业务状态。设备端 `final` 仅表示设备处理完成；LIS 结果必须先处于待审核状态，再由操作员审核生成正式报告。纸质标签、物理仪器、浏览器操作不在本脚本验收范围。

使用 `TEST-API-时间戳` 患者及申请，医院/科室使用“接口测试”名称和 `TAH-`、`TAD-` 编码。不清空数据库，不修改既有患者/结果。失败运行的模拟主数据保留用于追溯；删除或停用需按其引用关系处理。

### 本轮发现并修复的阻断

1. API 建单未存申请日期，后续采集被必填校验阻止：接收时补齐。
2. 采集已保存后，可选“记住送检方”字段为 null 导致返回 500：统一按 false 处理并补绑定测试。
3. FHIR 结果未携带目录精度，13.5 在审核中截成 13：传递主结果组件及小数位；超精度拒绝，不隐式截断。
4. 采集后外部申请号、编码及科室引用丢失；没有 LOINC 的结果缺少编码：保留来源映射并补稳定 GUID 输出。

失败调查用模拟申请 `DEV01260000000000022`（缺申请日期）和 `DEV01260000000000023`（修复前精度问题）保留为缺陷追溯数据，不能作为验收通过记录，也不修改其已审核结果。所有 TEST-API 项目均禁止临床使用。测试夹具还暴露目录描述唯一约束的错误提示仍为 500；脚本改用唯一描述，不代表该管理接口错误提示已修好。

### 未通过 / 待交付

1. **中文 PDF 报告未通过。** 旧 `patientHaitiClinical` 模板虽然生成一页 PDF，申请号和 13.5 % 存在，但仍有英法文标签，中文患者姓名、项目名未完整显示。不可对外发放为正式中文报告；需要专门修复模板、中文字体及字段版式。
2. **真实 HIS / 仪器尚未联调。** 需要厂商接口文档、脱敏报文、测试地址和授权方式；还需确认患者/就诊标识、申请号、科室/医生编码、项目与单位映射、撤单更正规则、报告回传确认。
3. **临床上线未验收。** 多项目、异常/危急值、不同岗位权限、并发结果、真实仪器和纸质标签打印等不能由此次单项目模拟通过代替。浏览器交互本轮未重新验收。

## 标准依据

- [FHIR R4 ServiceRequest](https://hl7.org/fhir/R4/servicerequest.html)：检验申请、引用关系及单项服务语义。
- [FHIR R4 HTTP](https://hl7.org/fhir/R4/http.html)：资源读写、错误与条件交互。

本实现为受限 FHIR R4 试点接口，不声明已通过 IHE 一致性认证。
