# 首次开单多管标本事务：限定验收

本批目标：复用已有普通 REST `saveEntry`，显式提交 `requestedSpecimens` 时将全部逻辑标本申请纳入开单事务；同类型多管不合并。沿用现有实体、主数据和权限查询，不新建报告/回执框架。

## 本批合同及退出断言

- 字段缺省维持旧流程；显式字段只接受首次 `orderEntryOnly` 开单。编辑、已有编号、采集 XML 或逐管标签不可混入并被静默忽略。
- 服务使用实际保存的申请和服务端当前用户。客户端不得指定标本申请 ID、申请归属、状态或已采集标本 ID。
- 全批先验证：有限正数量、顺序、活动标本类型/单位、项目存在/可下单/类型关联/注册权限、组合与当前类型的有效成员关系。失败返回中文定位信息，零部分标本插入。
- 两管同类型保存两个独立 ID；中途插入失败、无效/重复 ID、标签失败均退出同一事务。未取得事务提交成功不能作为保存成功。
- 组合按现有类型关联取本管成员，不要求跨类型成员属于当前一管。项目码与组合码使用真实 ID，不使用名称猜测。
- 保留患者、程序、EQA、外部编号和申请级标签链路。逻辑标本申请 ID 不是实体标本 ID，逐管标签留在采集后的既有流程。

## 边界

本批未切换前端的多 HTTP 保存链；新字段由实际 REST 服务消费并通过限定服务/代理回归验证，不等于用户界面已经使用整单保存。后续必须连同完整保存结果、持久唯一提交标识、授权恢复查询切换前端。

隔离数据库条件尚待确认；本批仅 SIM 内存夹具，不启动 Docker、不接真实库、不签发/打印/连接设备。真实数据库约束、并发、迁移、提交断连、前端与实际 HTTP 认证链测试仍未完成；不更新 18080、不关闭 AC14 或报告 P0。

## 下一步与未闭合风险

- 组合合同采取更严格拒绝：本管类型的所有有效可下单成员都必须显式包含且有登记权限。旧展示曾按用户权限取交集，本批不是与该部分展示完全等价；前端切换时需显示组合失效/权限变化，不默默少开项目。
- 既有历史采集逻辑还会展开组合全部成员；需在同一工作流后续核对按管类型边界，不能因本批保存通过就称采集已适配。
- 已有编号预查是误操作防守，查询和插入之间仍有并发窗口。持久唯一提交标识、同内容重放/冲突、完整权威结果及资源授权查询尚未实现；不把返回DTO或最近会话值当持久回执。
- 当前前端仍为申请保存后分别创建标本请求。后续必须接入整单路径，验证新旧版本兼容、超时/刷新/跨客户端恢复；未切换前不得宣称页面已修好或整单保存已投用。
- 本批不接真实数据库、不启动Docker、不改真实患者、不签发/打印/连接设备、不推送远程、不部署18080；M0/M1及M2～M7整体状态不改变。
