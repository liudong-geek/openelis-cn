# OpenELIS 中国医院版生产交付计划

> 版本：v2.0  
> 基线日期：2026-09-01  
> 目标：达到单院、常规临床检验范围内可正式上线、可验收、可运维、可追溯的生产级 LIS 交付水平  
> 当前判断：业务试用候选；生产交付成熟度约 40%～45%

## 1. “100%交付”的定义

100% 不是页面数量或代码提交比例，而是**签字范围内所有交付门禁全部通过**。任何一个 P0 门禁未通过，项目状态都不能标记为生产交付完成。

100% 交付必须同时满足：

1. 签字范围内业务用例通过率 100%，P0、P1 未关闭缺陷均为 0。
2. 患者、申请、标本、结果、审核、报告和审计数据全链一致，无孤立、串号或静默覆盖。
3. 医院主数据完成导入、映射、对账和业务负责人确认。
4. 真实 HIS/EMR 和范围内真实检验设备完成端到端联调，不以模拟接口代替。
5. 中文报告、标签和现场打印完成样张签字，报告修订、撤回和版本追踪可用。
6. 危急值、标本拒收重采、结果退回复检、报告修订等医疗安全事件完整闭环。
7. 所有岗位完成允许操作和禁止操作验收，敏感操作具备审计证据。
8. 可复现构建、安装、升级、回滚、监控、告警、备份和恢复演练全部通过。
9. 性能、安全和稳定性达到签字指标，正式试运行期间无未关闭 P0/P1。
10. 交付物齐全：软件包、版本清单、配置、接口文档、主数据、测试报告、操作手册、培训记录、运维手册和验收记录。

## 2. 首期交付边界

### 2.1 默认纳入范围

- 单院临床检验：临检、生化、免疫、凝血、尿液等常规专业组。
- 患者档案、检验申请、采样、运输交接、签收、拒收重采、贴签、分发、检测、结果录入、审核、危急值、报告发布和历史追溯。
- 项目、组合项目、标本、容器、科室、病区、床位、医生、仪器、单位、参考范围、危急值等主数据。
- 一个真实 HIS/EMR 接入通道，以及签字设备清单中的全部在用设备。
- 中文报告与标签、岗位权限、审计、质量控制、TAT、接口监控、备份恢复和生产运维。

### 2.2 必须在第1周锁定的范围

- 医院、院区、实验室和专业组数量。
- HIS/EMR、体检、收费、互联网医院等外围系统清单。
- 仪器型号、数量、连接方式、单向/双向要求和厂商联系人。
- 是否纳入微生物、病理、细胞学、免疫组化、POCT、输血或区域转诊。
- 报告模板、电子签名/CA、打印机和标签机型号。
- 历史数据迁移范围、保留年限、日申请量、峰值并发和可用性要求。

未在范围确认书中纳入的独立专业域不计入首期100%交付，但必须明确标记为“不启用”，不能以半成品菜单暴露给业务用户。

## 4. 交付原则

1. **证据完成**：代码合并不等于完成；必须有测试记录、截图/日志、数据核对和验收结论。
2. **主数据先行**：业务表单只引用受控主数据；禁止用自由文本长期代替科室、病区、医生、项目或单位。
3. **真实链路验收**：模拟服务用于开发，最终验收必须使用真实 HIS、真实设备、真实打印机和脱敏业务场景。
4. **医疗安全优先**：危急值、错样、拒收、修订、撤回、越权和数据串联问题优先于视觉增强。
5. **一个入口一个任务**：列表承担搜索、查看、新建和维护；历史信息作为患者/申请上下文，不重复建立孤立菜单。
6. **禁止静默失败**：接口、设备和保存失败必须进入可操作队列，具备责任人、重试、关闭和审计。
7. **禁止人工改库交付**：生产业务问题必须通过受控功能、迁移脚本或正式运维流程处理。
8. **逐门禁推进**：前一门禁未通过，不能把后续演示结果包装为整体完成。

## 5. 18周生产交付路线

多个工作流可以并行，但所有出口门禁必须按顺序通过。

| 阶段 | 周期 | 主要工作 | 出口门禁 |
| --- | --- | --- | --- |
| G0 范围与发布基线 | 第1周 | 锁定范围、盘点变更、建立发布分支/版本、功能路由和缺陷基线 | 范围确认书、变更清单、构建可复现、已知风险有责任人 |
| G1 主数据治理 | 第1～3周 | 建主数据模型、导入模板、唯一规则、启停用和映射校验 | 医院字典导入对账100%，业务负责人确认 |
| G2 报告与打印 | 第2～5周 | 重做中文报告、标签、签名、版本、修订、撤回和打印审计 | 中文样张、数字/单位/参考范围/异常标识和中文字体全部签字 |
| G3 核心流程与医疗安全 | 第3～7周 | 完成多项目、拒收重采、复检退回、危急值、修订报告和异常恢复 | 核心正负向用例100%通过，无 P0/P1 |
| G4 全页面产品化 | 第3～8周 | 路由清点、列表整合、表单栅格、状态反馈、空/错/加载态、响应式和中文术语 | 范围内页面逐页验收100%，无死链、首页误跳或半中半英 |
| G5 真实 HIS/EMR | 第5～10周 | 患者、就诊、申请、撤单、状态、报告、费用事件、台账、映射、重试和对账 | 真实接口全场景通过，积压消息为0，对账一致 |
| G6 真实检验设备 | 第6～11周 | 部署 Bridge，逐型号配置映射、结果接收、双向工作单、异常队列和断线恢复 | 签字设备清单逐台联调通过，重复/错配/离线场景通过 |
| G7 权限、安全与审计 | 第8～12周 | 岗位权限包、最小权限、敏感数据、会话、审计、依赖和渗透整改 | 全岗位允许/禁止矩阵100%通过，高危和严重问题为0 |
| G8 运维与非功能 | 第9～13周 | 性能、容量、监控、日志、备份恢复、升级回滚、时间同步和故障演练 | 峰值×2容量通过，恢复演练达标，告警和巡检可执行 |
| G9 全量回归与用户验收 | 第12～15周 | 自动化回归、全角色 UAT、打印和接口联合验收、培训 | 范围内用例100%通过，P0/P1为0，用户签字 |
| G10 受控试运行 | 第16～17周 | 脱敏/批准数据试运行、每日对账、缺陷闭环和上线演练 | 连续10个工作日无P0/P1，数据及接口每日对账一致 |
| G11 上线与交付归档 | 第18周 | 正式切换、回滚保护、现场支持、资料移交和验收归档 | 上线清单全通过、双方签字、进入质保/运维期 |

## 6. 各工作流完成标准

### 6.1 版本与工程质量

- 当前工作区基线：`develop@c6c6d61`，453个修改文件、189个未跟踪文件，共642项工作区变化。
- 必须形成变更所有权清单，区分产品改造、测试数据、构建产物、临时文件和上游变更。
- 建立可追溯发布分支、版本号、数据库迁移版本、镜像摘要和配置清单。
- 后端全量测试、前端单元测试、端到端测试、类型检查、格式检查和生产构建全部通过。
- 严重/高危依赖漏洞为0；构建警告必须清零或经书面风险接受。
- 每个发布候选必须能够从干净环境安装、升级和回滚。

### 6.2 主数据

- 明确数据所有者：HIS负责患者、就诊、科室、病区、床位和医生；LIS负责检验目录、标本、容器、单位、方法、参考范围、危急值和仪器映射。
- 所有主数据具有稳定编码、唯一规则、启停用、有效期、来源、版本和审计。
- 项目必须校验专业组、标本、结果类型、小数位、单位、参考范围、危急值和报告顺序。
- 不允许根据中文名称猜测映射，不允许未知编码自动落入默认项目。
- 导入后执行数量、唯一性、引用关系和抽样业务对账，结果为100%。

### 6.3 核心业务和医疗安全

- 覆盖门诊、住院、体检/其他签字来源，普通、急诊和补录场景。
- 覆盖单项目、多项目、多标本、合管、分管、部分完成和重复提交。
- 覆盖错码、未知码、拒收、重采、撤单、复检、退回、审核、发布、撤回和修订。
- 危急值必须完成发现、确认、通知、接收人确认、超时升级、关闭和审计。
- 已审核/已发布数据不可直接覆盖或删除；更正产生新版本并保留原记录。
- 患者、申请、标本、结果和报告全链路可从任一业务编号追溯。

### 6.4 页面与交互

- 建立范围内全部路由清单，逐页记录角色、入口、主任务、状态、空态、错态和下一步。
- 所有列表支持按业务关键字段搜索、查看、新建和维护；历史记录进入实体详情上下文。
- 表单使用统一栅格、字段宽度、标签、帮助、必填、校验和底部操作栏。
- 点击菜单、标签和按钮不得刷新到首页或丢失当前上下文。
- 1024、1366、1920宽度和200%缩放下核心操作可用；Chrome为主验收，Safari/Firefox补测。
- 用户可见文字全部为符合中国检验岗位习惯的中文，不出现原始键、英文兜底或直译歧义。

### 6.5 HIS/EMR 接口

- 独立接口账号、TLS、来源白名单、权限范围和审计。
- 消息具有来源系统、业务号、幂等键、状态、原文、响应、重试次数、责任人和关闭原因。
- 支持患者/就诊同步、检验申请、修改/撤销、采样/接收/检测/审核状态、结果/报告回传和回执。
- 代码、单位、科室、医生、项目和标本映射可配置并具备未映射工作队列。
- 支持失败重试、人工修复后重放、重复消息、乱序消息和外围系统停机恢复。
- 每日自动对账申请数、撤单数、结果数、报告数和失败数。

### 6.6 检验设备

- Analyzer Bridge 是设备通信运行主体，OpenELIS 负责配置、注册、接收、映射和结果处理。
- 每台设备记录厂商、型号、序列号、协议、IP/端口或串口、专业组、项目映射和启停状态。
- 验收连接、单向结果、双向工作列表（如范围要求）、质控、异常标识、单位、精度和设备原始报文。
- 覆盖断线重连、重复结果、未知样本、未知项目、错单位、超精度、乱序和高峰批量导入。
- 设备结果只能进入待审核，不得凭设备 `final` 绕过 LIS 人工/规则审核。

### 6.7 报告、权限和审计

- 中文报告支持患者身份、申请、标本、项目、结果、单位、参考范围、异常标识、审核人、签发时间和版本。
- 报告发布、打印、撤回、修订、重新发布和回传均有审计。
- 岗位至少包括开单员、采样员、接收员、检验员、审核员、报告员、主任、接口/设备管理员和系统管理员。
- 同时验证菜单、页面和接口权限，不能只隐藏菜单。
- 审计记录禁止被普通业务角色修改，且支持按患者、申请、操作者和时间查询。

### 6.8 运维和上线

- 生产与开发配置隔离，密钥不进入源码和日志。
- 建立数据库、附件、配置和密钥的备份策略；完成空环境恢复演练。
- 默认目标：RPO不超过15分钟，RTO不超过2小时；如医院签字要求更高，以签字值为准。
- 监控应用、数据库、磁盘、接口积压、设备离线、失败消息、证书、备份和业务TAT。
- 在签字峰值业务量2倍下执行容量测试；普通检索P95不超过2秒，保存类操作P95不超过3秒，具体以现场基线确认。
- 形成安装、升级、回滚、巡检、故障处理和应急联系人手册。

## 7. 测试与缺陷门禁

| 阶段 | 通过要求 |
| --- | --- |
| 每次提交 | 相关单元/接口测试通过，无新增类型、格式或构建错误 |
| 每周集成 | 核心冒烟、数据库一致性、主要路由和接口回归通过 |
| 发布候选 | 全量自动化及人工验收通过；P0=0、P1=0 |
| 用户验收 | 范围内业务用例100%通过，业务、接口、报告、主数据分别签字 |
| 试运行 | 连续10个工作日无P0/P1；接口、设备、报告和数据每日对账一致 |
| 正式上线 | 备份、回滚、监控、人员、资料、应急预案和上线清单全部确认 |

P2 缺陷只有在不影响业务、数据、医疗安全、权限、打印和接口的前提下，才允许由医院书面确认进入质保计划；核心页面不得带已知 P2 视觉或交互问题上线。

## 8. 团队与资源假设

建议最低配置：产品经理/检验业务分析1人、前端1人、后端2人（至少1人负责接口与数据）、测试1人、部署/数据库/安全1人；医院检验科关键用户、信息科、HIS厂商和设备厂商各指定固定联系人。

18周计划基于上述资源并行执行。若仅一人开发，预计周期至少扩大至2～3倍；若真实接口资料、设备权限或医院主数据延期，相应门禁不能按期完成。

| 输入 | 期望时间 | 缺失影响 |

## 10. 必交付成果

1. 需求范围与差异确认书。
2. 产品功能、状态机、角色权限和主数据字典。
3. HIS接口、设备接口、码表映射和消息处理文档。
4. 生产安装包、镜像摘要、数据库迁移、配置模板和软件物料清单。
5. 自动化测试、人工验收、性能、安全、恢复和试运行报告。
6. 中文报告/标签模板及样张签字记录。
7. 用户操作手册、岗位培训材料、管理员和运维手册。
8. 上线、回滚、应急、备份、恢复、巡检和质保方案。
