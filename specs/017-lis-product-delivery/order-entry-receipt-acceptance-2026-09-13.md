# 首次开单持久回执：限定代码检查点

日期：2026-09-13。关联唯一 v3 计划的 AC08、AC14、AC18；本记录不是正式交付验收。

## 用户操作及实现范围

仍复用原 `POST /rest/SamplePatientEntry`。未来前端整单保存传入唯一 `Idempotency-Key`，同一次提交必须保留该标识和原始序列化报文；未带头的旧入口暂时不变。前端尚未切换，因此不能声称浏览器中的重复开单问题已经彻底解决。

- 请求头是严格规范的小写 UUID；完整原始 JSON 按版本 `raw-json-v1` 摘要绑定，实际读取上限 16 MiB。重复头、重复 JSON 键、空/畸形/多文档报文拒绝；捕获缺失不得退回旧保存路径。未知字段、程序问题及文档内容也参与摘要，空白/字段顺序变化会冲突，客户端必须冻结原始报文，不得重新序列化后盲重试。
- 已有显式多管开单事务外新增协调器：核对当前操作人、查询原回执、同事务认领唯一标识并立即 flush，然后调用原校验和 `saveEntry`，核对实际患者/申请/全部逻辑标本管/申请级标签，完成回执。认领、业务保存或完成失败向事务外抛出；不在失败的持久化上下文重查并重写。
- 核对实际标本请求集合与原输入、保存回填 DTO 的数量、唯一 ID、归属、顺序、类型、数量、单位、项目/组合及 REQUESTED 状态。少管、多管、另一申请的管、错误项目不能报成功。逻辑标本请求 ID 不等于采集后实体标本 ID。
- 已有患者不允许保存过程中换 PK；新患者使用服务器新回填 PK；EQA 只允许保存前捕获的配置患者替换，无配置时保留原合同。环境样本拒绝残留临床患者 PK，并检查实际无患者关联。
- 标签预期在保存前复制，与实际申请级标签记录比对。回执代表已保存的标签请求，不代表生成 PDF 或打印出纸。
- 相同标识/原报文重放先于首次创建校验，返回原不可变快照，不重新调用开单或 STAT 通知；不同内容冲突、其他用户拒绝。`GET /rest/SamplePatientEntry/submissions/{submissionId}` 重新核对当前身份、所有者和全部检验项目的当前登记访问权限，仅读原回执，不用普通申请详情猜测。
- 请求失败且结果未知时返回中文提示、保留标识、不宣称回滚；恢复 404 明示原请求可能仍在处理，不是可重新开单的证据。响应禁止缓存，不暴露底层异常。快照版本/摘要版本/时间及标签结构损坏拒绝。时间在写入前统一到毫秒，避免任意纳秒值被数据库精度缩减。
