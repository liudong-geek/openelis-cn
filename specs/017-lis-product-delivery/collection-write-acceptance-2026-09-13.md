# 采集专用保存与逐管绑定（限定验收）

日期：2026-09-13。接续 v3 顶部“当前申请读回＋明确恢复”主批，收口既有 collection-only 写入，不新建菜单、回执平台或平行业务模型。

## 本批结果

- 采集专用请求在普通表单初始化之前分流；只处理已保存申请的采集字段，不把旧患者、送检方或申请表单内容复制回数据库对象。原 HTTP 请求进入已有操作人门禁，不接受只有数字用户 ID 的身份兜底；保存末尾和事务提交前复核身份与项目权限。
- 每管必须携带明确的标本申请 ID，按当前申请归属、类型和状态核对。支持同类型多管及先采其中一管，不以类型或显示次序猜测绑定；显示次序重复不等于身份重复，已作废实管占用的条码序号不得复用。
- 新采集沿用服务端已保存、已展开的检验项目计划。组合项目发生变化时不能静默增加未申请项目，也不把其他标本类型的组合成员带入；类型、项目、组合关系及有效性、数量、单位、时间和登记权限在第一笔写入前统一检查。
- 区分“存在实管但尚未采集”和“原已采集记录的重复核对”。前者仍执行真实采集校验，通过保留旧基线的 detached 对象调用原审计更新服务，不重复创建分析；后者核对原申请、实管、采集时刻和实际分析覆盖后完全只读，不改写历史采集人员、数量、单位、时间或审计字段。历史主数据停用本身不阻断已采集事实的只读重放。
- 错管、取消、作废、拒收、重复请求、缺少实际分析、失效权限及异常插入回执拒绝本次操作。真实 Spring 事务代理的 SIM 资源测试覆盖第二管分析失败、关联失败、方法返回后权限变化和身份变化的整批回滚。
- 错误按 400/401/403/409/503 分流并禁止缓存；未知结果告知重新核对，不回退到普通整单保存、不返回底层患者报文。

## 产品交互边界

本批是恢复采集的后台前置，不是新增可演示页面。现有“核对当前申请”仍只读，尚未接入本次专用保存；不得据此开放“采用并继续采集”，不得将 current DTO 当完整编辑表单。未进行本批浏览器验收或真实前后端联测，也未声称原申请页面已全部变好。

下一主批仍在同一申请工作区：在现有一致性读取中补齐采集所需上下文、前置状态和有效主数据名称；明确确认采用完整当前事实后，接入只提交采集字段及逐管请求 ID 的保存，保留部分采集及未采集管。取消旧整单加载/写入回退，覆盖未知结果重新核对、会话变化、剩余管选择和清晰的下一步。获准隔离库后，再验证首次保存→刷新核对→部分采集→再次恢复。
