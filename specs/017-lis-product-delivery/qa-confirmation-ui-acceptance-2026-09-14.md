# 原申请工作区的全部标本核对：前端限定验收

日期：2026-09-14。基线 `4e4b37cf8`，接续后台 `be09f8d3d`；唯一执行计划为交付计划 v3。本批不是医院交付验收，也没有更新 HTTP 18080。

## 本批产品行为

原“核对当前申请”工作区显示本申请完整实管、管码、类型、签收时间和实际核对配置，不新增菜单。清单初始空选；用户逐项核对后进入确认页，确认页以高对比只读清单显示冻结内容，只有明确点击才提交一次。返回核对不会提交。

专用 POST 只返回确认回执；页面另行读取原 current，核实同一确认编号、事实摘要、完整管集合、清单版本和署名时间后显示“核对记录已保存并核实”。旧 allRequiredVerified、不完整回执、别的确认、STALE/INVALID/BLOCKED 和仅 HTTP 200 均不能获得成功。

坏 QA 合同仅阻断核对区，不丢失合法患者/采集当前记录。缺管、重复管码、未签收、异常标本、坏配置/规范时间版本均不给本批确认能力。保留后台原始 UTC 微秒，不用本机毫秒值重建清单版本。

发送前保存并回读匿名保护信息，仅存原开单核对码、确认 UUID、随机盐及摘要；不存患者/实管正文、清单文本、命令或凭据。超时、401/403/409/500、坏回执及读回失败保持保护；刷新只查询原核对码，不重发。只有相同确认及当前事实完全匹配才消解；确认后事实已变化、长期/跨客户端未知仍须后续恢复机制或管理员核实。

采集、签收、标签、新旧保存与 QA 操作互斥。会话暂停再恢复、换会话、卸载和迟到回包不能复活旧能力。旧 QA 保存开始同时废弃私有 current 和在途 current 查询，必须重新查询后才可新建确认。

## 不得认定为已完成

本批是**整申请全部实管的人工核对记录**，不是逐管临床接受/拒收结论或检验放行，`currentAcceptanceVerified` 仍为 false。不会自动改 QA 工作流完成状态、录入/审核结果、打印或签发报告。

源码归档不是数据库/配置备份，也不是固定可运行回退版。只有同一候选全部适用门禁及授权数据库/配置备份、可运行回退齐备后，才可替换本地 HTTP 运行版；本批不启动 Docker、旧业务栈或真实接口。
