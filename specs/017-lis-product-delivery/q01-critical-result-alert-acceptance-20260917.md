# Q01 配置化危急值与通知闭环验收记录

日期：2026-09-17

## 本批范围

本批复用检验项目目录已有的参考范围和告警规则，不写入任何真实医院阈值。医院资料尚未提供，因此所有示例名称、数值和通知说明均为合成数据，只用于证明配置、计算、告警和确认链路可工作。

## 已实现行为

- `CRITICAL` 规则按照结果所属项目、患者年龄/性别及标本类型选择既有 `result_limit`，只对配置了有限危急值上下限的数值结果判定。
- 普通数值严格越过阈值时触发；分析仪上传的 `>阈值`、`<阈值` 在边界也能按其方向触发。非数值结果和未配置的无限边界不触发。
- 勾选“需要确认”的危急值规则生成 `CRITICAL_RESULT` 告警。告警与已保存的 Result ID 唯一绑定，重复计算和请求重放返回首次记录，不改变首次消息、上下文或重复计数。
- 首次上下文冻结结果、分析、项目、规则、实际值、数值、方向、命中阈值、范围记录、触发人及 SHA-256 证据摘要。
- 危急值告警只能由当前登录会话用户确认；请求体中的用户 ID 不参与授权。确认必须填写说明，保存确认人、确认时间和确认说明。
- 数据库约束保证危急值告警类型、严重级别、Result 归属、证据摘要、唯一结果和非空确认说明；触发器阻止首次消息和证据上下文被后续状态更新改写。
- 质量预警中心增加“危急值结果”筛选和中文文案，并移除与通用告警接口重复的旧 EQA 确认入口。

## 配置入口

1. 在“基础配置 → 检验项目”设置对应年龄、性别和标本类型的危急值下限/上限。
2. 在同一项目的“告警”区新增 `CRITICAL` 规则。
3. 如需闭环，在规则中开启“需要确认”；站内通知可配置角色，外部模拟可使用自定义短信或邮箱收件地址。

医院正式启用前必须用获批的危急值表替换模拟阈值，并完成科室、医生、短信/邮件网关和电话回读 SOP 的现场验收。

## 验证结果

- Java 21：生产源码编译和 WAR 构建通过，Jacoco 分析 2961 个类。
- 后端无容器测试：4 个测试类、17 项通过，覆盖上下限、分析仪不等号、无阈值不触发、持久告警、全生命周期重放、确认备注和会话操作者。
- 前端：5 个测试文件、24 项通过；Prettier 检查通过。
- 中文：交付检查覆盖 1874 个被引用文案 ID，通过。
- PostgreSQL 14.24：迁移从 852 增至 853；唯一结果、证据形态、确认说明、证据防篡改和回滚零残留通过。
- 浏览器：真实 `AlertsDashboard`、`AlertsTable` 和 `AlertAcknowledgeModal` 使用同源内存模拟，完成“待处理 1 → 必填确认说明 → 已确认 → 待处理 0”。
- 前端正式构建：2656 个模块通过；预览构建 1430 个模块通过。
- 全仓 TypeScript 基线门禁仍在 17 个既有非 Q01 文件中报告诊断，本批修改的 JSX/JSON 文件没有 TypeScript 诊断。

由于本机没有 Docker，依赖 Testcontainers 的历史 Spring 集成测试无法在候选区启动；本批使用无容器服务测试和独立 PostgreSQL 14.24 实例分别覆盖业务逻辑与数据库约束。写回原项目后再次执行相同范围。
