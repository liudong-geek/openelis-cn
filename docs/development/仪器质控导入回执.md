# 仪器质控导入回执

更新日期：2026-10-20。状态：质控异常闭环修复候选说明；需求 C-03／D-03／E-01，变更 CHG-157／160。本文说明候选代码的响应与持久化语义，不作为部署或医院接口验收证据。操作人员核对步骤见[用户手册第8.4节](../product/china-lis-user-manual.md#84-仪器质控待处理)。

## 入口与范围

适用入口为 `POST /analyzer/fhir`，由 `AnalyzerFhirImportController` 接收 FHIR Bundle，转换为 `AnalyzerResults` 暂存候选。新 QC 原件由 `QCStagingService` 保存，按暂存 ID 调用同一批次解析与 QC 创建服务。原暂存表持久保存批号、水平、原 Observation、来源摘要、处理状态及结果关联，不另设并行导入队列。Westgard 与临床放行条件保持。

暂存服务正常返回后，即使部分 QC 未处理或结果未知，仍返回 HTTP 200 和 `success=true`，避免把后处理失败当作整包接收失败。数据接收、QC 记录创建和规则合格是三层不同结果；接收方必须分别核对。QC 创建计数在事务代理正常返回后增加，创建异常不计成功。

不合法 Bundle 类型、没有可转换的 Observation 和导入异常仍沿用原错误响应。本次没有统一改造接收阶段的未知提交结果；遇到超时、连接中断或错误响应，不能仅凭响应推断所有暂存写入均未发生，应先查回核对。

## 汇总字段与兼容语义

| 字段 | 候选版语义 |
| --- | --- |
| `success` | 暂存服务正常返回的接收回执；不代表每条 QC 已创建或规则合格。 |
| `resultsInserted` | 保留旧语义：本次转换为暂存候选的行数，包含被去重跳过的行；不是实际新增行数。 |
| `resultsReceived` | 与 `resultsInserted` 相同的候选行数，以明确名称补充旧字段。 |
| `stagingRowsInserted` | 暂存服务返回后具有非空 ID 的本次候选行数。 |
| `stagingDuplicatesSkipped` | 候选行数减去实际新增暂存行数。 |
| `qcResultsReceived` | 暂存候选中标记为 QC 的行数，与 `qcOutcomes` 条目数相同。 |
| `qcResultsProcessed` | 本次返回 `CREATED` 的 QC 行数；不再包含未匹配批次、非数字、创建异常或重复跳过。 |
| `qcResultsNotProcessed` | 本次返回 `NOT_PROCESSED` 的 QC 行数。 |
| `qcResultsUnknown` | 本次返回 `UNKNOWN` 的 QC 行数。 |
| `qcResultsDuplicateSkipped` | 本次返回 `DUPLICATE_SKIPPED` 的 QC 行数。 |
| `qcProcessingComplete` | 未处理、未知和重复跳过三项均为零时为 `true`；没有 QC 行时也为 `true`。它不表示规则合格。 |
| `qcOutcomes` | 当前请求逐项 QC 回执数组。 |
| `analyzerId` | 本次解析得到的仪器 ID；未解析时为 `null`。 |

计数范围是成功转换为暂存候选的 Observation，不是原 Bundle 中所有条目。缺少样本号或结果值而在映射阶段被跳过的 Observation 不计入这些字段。各 QC 状态计数之和等于 `qcResultsReceived`。

## 逐项回执

每条 `qcOutcomes` 包含 `analyzerResultId`、`accessionNumber`、`testId`、`status`、`qcResultId`、`reasonCode`。`analyzerResultId` 是本次新增暂存 ID；重复跳过时不返回原暂存 ID，而是 `null`。只有 `CREATED` 返回非空 `qcResultId`。

| `status` | 含义与处理 |
| --- | --- |
| `CREATED` | QC 创建服务正常返回且取得非空结果 ID；还需查询实际规则评估和受限状态。 |
| `NOT_PROCESSED` | 本次未满足 QC 创建条件，按 `reasonCode` 核对原数据和配置。 |
| `UNKNOWN` | QC 调用或提交阶段抛出异常，当前回执不能确认最终结果。先查回实际记录，不自动重发整包。 |
| `DUPLICATE_SKIPPED` | 既有暂存去重逻辑未新增该行，本次不再创建 QC；不代表原 QC 已创建或通过。 |

| `reasonCode` | 对应含义 |
| --- | --- |
| `QC_ANALYZER_NOT_RESOLVED` | 未解析到仪器。 |
| `QC_TEST_NOT_MAPPED` | 未获得有效项目映射。 |
| `QC_CORRECTION_REQUIRES_REVIEW` | 明确更正或同一来源检测身份内容变化，保留原件待核对，不覆盖原 QC。 |
| `QC_CONFIGURATION_REQUIRED` | 暂存行只读或带有导入问题。 |
| `QC_NON_NUMERIC_RESULT` | 结果不能转换为数值。 |
| `QC_REQUIRED_FIELD_MISSING` | QC 服务所需仪器、项目、样本号、结果或时间缺失。 |
| `QC_CONTROL_LOT_NOT_RESOLVED` | 批号未知、不可用、重复、水平冲突或不能唯一匹配，不选择另一批号替代。 |
| `QC_PROCESSING_OUTCOME_UNKNOWN` | QC 调用或提交回执无法确认；先按暂存 ID 查回持久关联，不自动重发。 |
| `QC_PROCESSING_PENDING` | 已保留原件，尚未处理。 |
| `QC_LEGACY_REVIEW_REQUIRED` | 历史记录缺少可信原件或关联，禁止直接重放。 |
| `DUPLICATE_STAGING_SKIPPED` | 本次暂存去重跳过。 |

`CREATED` 的 `reasonCode` 为 `null`。创建服务返回空记录或空 ID 也不能计为成功，会转为未知回执。

## 批次与原件身份

明确批号只在同一项目和仪器下精确匹配；提供水平时联合该水平确定唯一候选。同批号的不同水平可以共存；同批号、同水平重复时不能按状态或查询顺序择一。未知、停用、身份歧义或冲突立即待处理，不回退至另一批号。未提供批号时保留旧标本号作为批号的兼容路径；其后有水平时仅匹配唯一可用水平，确实缺少明确身份时才采用唯一可用批次。ACTIVE 与 ESTABLISHMENT 沿原能力使用，不新增院方有效期制度。

新 QC 的来源摘要绑定仪器、已解析标本号与规范化原 Observation。仅对象键排序，保留数组顺序；原文独立保留。相同原件重发跳过，数据库唯一约束及仪器行锁防止并发重复。原测定时间、值、批号、水平、项目等任何原文内容变化均不会因“时间相同或值相同”直接被吞。没有可靠仪器检测 ID 时，不能声称跨任意改写报文的 exactly-once。

明确 corrected/amended，或同仪器、同 Observation.id 和原 effectiveDateTime 出现不同原件时，保留更正原件待核对。不用本地补出的时间或当前项目映射生成检测身份，不覆盖既有质控。患者暂存沿原值/时间合同，QC 与患者记录隔离。

## 查询与人工补处理

前端直接入口为“质量管理 → 仪器质控待处理”。该页面及二级菜单允许 `Global Administrator` 或 `Lab Supervisor`，与既有 `/rest/qc/imports` 后台授权一致。常规“质量负责人”模板不自动包含上述授权；其他质控和批号配置页面的权限保持原状，配置维护由具有相应权限的人员操作。不能用隐藏菜单代替后台授权。POST 还要求有效会话用户 ID，处理人使用该用户。

| 接口 | 行为 |
| --- | --- |
| `GET /rest/qc/imports?status=OPEN&limit=20&offset=0` | 有界分页，返回 rows/total/limit/offset；OPEN 包含 PENDING、NOT_PROCESSED、UNKNOWN。ALL 可查成功与历史记录；列表不返回原 Observation。 |
| `GET /rest/qc/imports/{id}` | 在服务事务内准备同一 QC 原件、原因及已有结果关联；不返回患者暂存记录。 |
| `POST /rest/qc/imports/{id}/reprocess` | 使用已存原件，锁定该行；已有结果关联时返回原结果，没有关联时校验后创建，创建与关联同事务提交。请求不接收替换批号、读数或项目。 |

处理状态为 PENDING、NOT_PROCESSED、UNKNOWN、CREATED、LEGACY_REVIEW。只有确证关联到已创建结果才关闭导入待处理；确认查看不等于处理成功。处理后的状态、原因、结果关联和操作人员变更沿已有审计服务保存。

QC 提交异常从事务边界抛出，调用者另开事务锁行查回。已有结果链接则返回 CREATED；否则保留 UNKNOWN。人工先刷新同 ID，再明确决定是否补处理；不自动重试，不使用整包重发恢复。HTTP 200 表示已有明确 CREATED/NOT_PROCESSED 回执，202 表示 UNKNOWN，查回仍不可用时503并保留UNKNOWN语义。

新 QC 及历史控制记录不随患者结果接受清理而删除。迁移保留旧值和患者记录，旧无关联控制记录标记LEGACY_REVIEW，不能猜测其是否已创建QC。结构回滚在存在新原件时拒绝，使用对应数据库备份回滚；不能通过删列丢弃原件。

## 保留边界

项目未映射、非数值、只读及更正记录继续待核对，不在此页编辑或自动纠正原始仪器数据。ASTM 原错误重放与 FHIR QC 补处理仍是各自入口，没有新增应用内文件监听服务。历史记录关联修复、任意改写报文去重、医院实际设备映射及院方更正制度另行验收。

本批局部服务、真实数据库、权限/HTTP、页面、完整发布及真实医院接口分别记录。QC 创建仍不表示Westgard已评估、质控合格或允许临床放行。
