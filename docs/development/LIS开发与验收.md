# LIS 开发与验收

日常修改验证受影响行为，集成修改核对共同调用者，发布验证整个交付版本。三种范围复用原测试；失败记录、测试身份和业务数据保留。

## 日常修改

在 `frontend/` 执行，明确给出文件：

```sh
npm run test:feature -- src/components/admin/ProviderMenu/ProviderMenu.test.jsx
npm run check-format:files -- src/components/admin/ProviderMenu/ProviderMenu.tsx
npm run format:files -- src/components/admin/ProviderMenu/ProviderMenu.tsx
```

`test:feature` 不接受空范围。真实不符合项日历使用自己的配置；患者日期控件同时检查普通测试及真实日历。命令本身不启动 Docker、构建前端或执行整套浏览器测试。类型或共享类型有变动时运行 `npm run typecheck:delivery`；文案运行 `npm run check:i18n:delivery`。样式和交互同时核验实际页面。

后端日常使用指定类，保留增量编译，使用已有本地依赖时可加 `-o`：

```sh
mvn test -Dtest=TestCatalogEditorBasicInfoIntegrationTest -DforkCount=1 -DreuseForks=false
```

多种 Spring 测试上下文不可共享旧静态事务管理器，相关集成类使用独立JVM；不是跳过断言。依赖没变时不重建dataexport。主项目插件测试JAR仍需保留，不用 `maven.test.skip=true` 代替编译该产物。

Spotless 2.43 的 `spotlessFiles` 是匹配**绝对路径**的正则列表，相对文件名可能匹配零文件却返回成功。局部格式传入经正则转义的绝对路径，并检查输出实际匹配文件数；全仓格式化仅在确实需要时运行。此项不等于依赖升级。

## 集成修改

| 修改内容               | 检查范围                                                    |
| ---------------------- | ----------------------------------------------------------- |
| 公共表单/导航/当前对象 | 所有实际调用者、旧链接、取消、保存后刷新及查询分页          |
| 请求处理/状态          | 成功、拒绝、未知结果、断流/超限、取消、登录切换、并发与身份 |
| 事务/数据库/权限       | 指定服务及真实数据库、越权、版本冲突和写后读取              |
| 依赖/构建/全局配置     | 生产构建、相关测试和代表性页面                              |

浏览器日常按原项目和明确文件执行。共享数据库保持单worker。视频、人工设备演示与核心回归分开；不把它们全部塞进每个小修改。

## 完整发布

1. 冻结候选提交及构建来源，运行 `npm run check:delivery`。该命令包括中文检查、类型基线比较、完整单测、患者与不符合项真实日历、生产构建。
2. 后端执行适用完整构建/测试；需要插件时保留主项目tests JAR。使用同提交的WAR和前端dist，避免测试一版部署另一版。
3. 在明确归属的隔离环境运行原34个Cypress文件、349业务场景及跨岗位流程；保留身份、权限、负向、写后读取、原超时和失败终止。当前结果准入以真实结果清单验证，历史验收标记不作为当前放行依据。
4. 备份现有业务库并验证恢复，保留原镜像/配置和回滚入口；更新中文手册、PDF、运行版本；部署后检查实际页面。

`run-ci-checks.sh` 是完整后端CI检查入口，默认会clean和构建依赖，不作为日常单文件验证命令。局部测试通过、仅构建成功、类型基线通过分别记录，不能笼统记为完整验收。

## CI分流

前端和后端固定检查点须核对被选中任务确实成功，不能把意外跳过算通过。纯文档PR可跳过E2E重构建，但固定检查点明确标注文档范围。源码、配置、锁文件、迁移、测试、运行包内手册，以及主线推送/发布/手动执行保留完整门禁。具体来源校验和跨仓约束由E2E架构说明及工作流维护，不复制第二套规则。
