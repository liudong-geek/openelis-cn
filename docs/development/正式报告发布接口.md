# 正式报告发布接口

本合同对应 C-01、D-03、E-01 与 CHG-158（2026-10-18）。已确认规则为：结果统一在正式报告签发后对外发送。适用入口包括手动导出、定时导出及 FHIR 主动查询。

## 发布来源与版本

临床发布内容唯一来源为已签发版本保存的冻结快照和正式 PDF。结果审核完成、本地 FHIR store 存在资源或出站任务已登记，均不构成正式发布资格。发布过程不读取当前 Result、患者资料或字典补齐报告内容。

当前 schema 1 未冻结结构化结果的行身份和标准编码绑定，只提供 PDF 原件型 `DiagnosticReport`，不生成 `Observation`。入站结果接收及内部录入、审核流程保持原合同；入站写入返回技术确认及资源 ID，不返回未签发临床结果。

| 项目 | 合同 |
| --- | --- |
| 资源身份 | `DiagnosticReport/cn-report-<releaseId>`，同一签发版本使用固定 ID |
| 正式报告 | `status=final`；更正版本为 `amended`，携带前版引用及更正原因 |
| 原件 | `presentedForm` 为已保存的 `application/pdf` 字节 |
| 版本证据 | identifier 包含报告文档、编号、版本、release ID、冻结内容 SHA-256 和 PDF SHA-256 |
| 作废 | 同一资源 ID 返回 `entered-in-error`、作废原因及签名信息，不含 PDF 或结果资源 |
| 失效版本 | 草稿、被更正替代的版本不再作为当前发布内容；历史原件查询仍走原有受控入口 |

identifier 的 system 使用 `org.openelisglobal.oe.fhir.system` 去除末尾 `/` 后的命名空间，后缀为 `/report-document`、`/report-number`、`/report-version`、`/report-release`、`/report-frozen-sha256`、`/report-pdf-sha256`。报告版本值为 `<reportNumber>:V<version>`。患者与签发人的 identifier 属于本地身份，尚不代表医院主索引映射。SHA-256 不写入具有不同摘要约定的 `Attachment.hash`。

实现：[冻结投影](../../src/main/java/org/openelisglobal/report/service/impl/IssuedReportFhirProjection.java)。

## 主动查询

以下路径相对于应用上下文。查询使用已认证用户身份，并校验整份冻结报告范围的权限，不返回仅有部分专业组权限的报告内容。

| 请求 | 行为 |
| --- | --- |
| `GET /fhir/DiagnosticReport/cn-report-<releaseId>` | 返回当前可发布版本或作废记录；不存在、未签发或已被替代时返回 404 |
| `GET /fhir/DiagnosticReport/<旧检验任务UUID>` | 仅兼容与报告成员精确匹配且唯一的已签发报告；无匹配为 404，多份匹配拒绝返回；作废查询使用正式版本 ID 或报告编号 |
| `GET /fhir/DiagnosticReport?identifier=<reportNumber>` | 按一个完整报告编号查询，返回最多 100 条可授权的当前报告或作废记录 |
| 带命名空间的 identifier | 接受 `<命名空间>/report-number\|<reportNumber>`，命名空间须与配置一致，实际请求需 URL 编码 |
| `GET /fhir/Observation/<id>` | 404，当前没有可发布的结构化签发快照 |
| `GET /fhir/Observation?...` | 422，当前不支持结构化签发结果查询 |

报告查询只接受单个非空 `identifier` 和可选 `_format`。重复 identifier、逗号多值、旧 subject/status/date 筛选及 `_include` 等参数返回 400。直接读取无完整权限返回 403；报告搜索按整份报告过滤无权限候选。签名、冻结内容、PDF 或身份不匹配时返回失败，不返回报告内容。

其他资源代理查询也检查返回 Bundle 及 contained 中的临床资源，遇到 `Observation` 或 `DiagnosticReport` 即返回 422 OperationOutcome，提示使用正式报告发布接口，不能通过 include 类查询转发旧缓存。Observation 的受控入站新增、更新仍保留，响应只返回技术确认及资源 ID，不回显未签发结果、患者信息或结果关联资源。

非临床多页代理暂不支持。Patient、ServiceRequest、Specimen、Practitioner、Organization 的搜索响应含上游 next、previous 等导航或嵌套 Bundle 链接时，整次请求返回 422 OperationOutcome，提示“暂不支持上游分页查询，请缩小查询范围后重试”。不会删除链接或总数后返回残缺的成功结果。正常单页保留条目及 total，self 链接重建为当前应用请求地址和原查询参数，不透出 store 分页地址。受控多页代理仍属 FHIR 联调待完善项，不表示完整兼容上游分页协议。

实现：[报告入口](../../src/main/java/org/openelisglobal/fhir/providers/DiagnosticReportProvider.java)、[结果入口](../../src/main/java/org/openelisglobal/fhir/providers/ObservationProvider.java)、[代理响应边界](../../src/main/java/org/openelisglobal/dataexchange/fhir/FhirUtil.java)。

## 导出装配与路由

[IssuedReportDataExportService](../../src/main/java/org/openelisglobal/dataexchange/fhir/service/IssuedReportDataExportService.java) 实现共同 `DataExportService` 接口并标记 `@Primary`。手动与定时调用使用该实现；外部库原 bean 保留，临床资源不委托旧实现透传。

| 配置 | 实际用途 |
| --- | --- |
| `org.openelisglobal.fhirstore.uri` | 非临床资源来源 |
| `org.openelisglobal.fhir.subscriber` | 实际接收端地址 |
| `org.openelisglobal.fhir.subscriber.resources` | 实际资源范围；包含 Observation 或 DiagnosticReport 时启用正式报告发送 |
| `org.openelisglobal.fhir.subscriber.resource.singleTransaction` | 非临床资源批次合并；正式报告仍逐份在锁内发送 |
| `org.openelisglobal.fhir.subscriber.resource.allowParallel` | 沿用同任务并发配置 |

任务的 `endpoint` 不覆盖全局 subscriber，任务上的资源清单也不覆盖全局 resources；任务 headers 继续传入客户端。缺少来源、接收端或资源配置时记录 `NOT_RAN`，不标记发送成功。

非临床资源沿用上次成功至本次开始时间的查询窗口和分页，允许 Task、Patient、ServiceRequest、Specimen、Practitioner、Organization、Encounter、Location、Device。旧本地 Observation、DiagnosticReport 不进入导出查询；嵌套临床资源、未知资源类型或未知写入形态使该次导出失败。Task 的旧 output 引用在发送副本中移除。

生产 [AppConfig](../../src/main/java/org/openelisglobal/config/AppConfig.java) 同时对 `org.itech` 启用组件扫描与 JPA repository 扫描。缓存依赖中的 `DataExportAttemptDAO` 为 Spring Data repository，`DataExportStatusServiceImpl` 为 Service，由生产配置装配。

## 发送前校验与重试

[ReportPublicationService](../../src/main/java/org/openelisglobal/report/service/impl/ReportPublicationService.java) 集中校验报告归属、当前状态、冻结范围及内容哈希、PDF 哈希、签名的版本身份、人员、时间、含义和签名原文。作废记录另校验真实作废签名。读取和发送均按报告文档、签发版本的顺序加锁并刷新状态；主动查询在锁前后校验完整报告权限，发送回调在锁内消费校验后的内容。

临床导出每轮从 ID 0 开始，以本轮开始时间为上界，按 ID 游标分批查询全部已提交的当前 ISSUED／VOIDED 候选，每页最多 100 个标量 ID。候选查询不加载全部 PDF，逐份取得锁后才生成发送内容。每轮重查保留了提交晚于前轮查询的报告，不能改成只按上次成功时间跳过旧时间戳。

正式报告使用 FHIR transaction 中的 `PUT DiagnosticReport/cn-report-<releaseId>`。同一版本重复发送使用同一身份，不创建新的本地报告版本。每轮可能重复 PUT；当前没有按接收方持久化的去重回执，不提供 exactly-once 保证。

接收端必须返回 transaction-response，条目数量一致且全部为 2xx，才计该次 transaction 成功。已成功部分事务后发生异常记为 `INCOMPLETE`，首个事务前失败记为 `FAILED`；无内容发送时仍须取得接收端 capability 响应。超时或失败不证明远端未写入。结果未知时，按接收端、固定资源 ID、版本和哈希核对远端资源及日志，再决定重试；不以重新签发新版本代替传输重试。

## 待办、传输与医院回执

| 记录 | 含义 |
| --- | --- |
| `HisResultOutbox` | 正式版本的 REPORT／AMENDMENT／WITHDRAWAL 发送意图 |
| `DataExportAttempt` | 共同 FHIR 导出的传输尝试及状态 |
| 医院业务 ACK | 接收系统按真实业务协议给出的接收、入库或撤回结果，须独立核验 |

签发与发送意图在同一事务登记。更正和作废关闭旧版本尚未送达的 REPORT／AMENDMENT 待办，保留已确认及已关闭历史。作废另登记 WITHDRAWAL；重试校验版本状态、事件、幂等键、载荷和签名，旧待办不能绕过当前发布准入。

出站意图不等于已执行发送，FHIR 2xx 不等于医院业务 ACK。`entered-in-error` 是本系统的标准化作废报文，尚不证明院方已撤回已接收内容。医院字段映射、认证、版本覆盖、撤回及 ACK 协议仍待真实联调。
