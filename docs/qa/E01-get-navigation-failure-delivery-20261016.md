# E-01：页面离开期间的 GET 失败交付

需求：B-01、E-01。基准 e2e00f397，限定共享 GET 的失败交付。

## 实际问题

a13 的原用户与条码场景出现三个 `TypeError: Failed to fetch`。被动网络记录把它们关联到同帧刷新或导航引起的 `ERR_ABORTED`。实际监听诊断中，早注册的 pagehide 监听退出后，GET 的拒绝微任务先进入 catch/finally 并移除了自己的取消监听；该监听没有机会执行。证据为交付工作区 `outputs/lis-six-batch-20261013/network-error-a13-diagnosis/navigation-listener-results/lifecycle.jsonl` 的 seq134–139。

## 修改

GET 失败处理等待下一事件循环任务，再决定是否报告错误及交付失败。等待期间保留 pagehide 和调用方取消监听。取消时清除计时器并结束等待，避免页面冻结后留下未完成的等待。

成功读取、POST、身份、权限及业务写入保持原行为。beforeunload 不用于取消，因此用户取消离开页面后请求仍可完成。当前页面的网络错误、JSON 解析错误及未由本请求取消导致的 AbortError 仍报告一次并回调 undefined；回调本身抛出的异常仍向调用方拒绝。

- 原14项生命周期测试保留，增加两个失败请求与pagehide竞争、调用方取消失败交付两项。旧源码14通过／2失败，候选16通过。
- 根在实际仓内复验生命周期、响应完成和幂等头三文件：20通过，耗时3.90秒。格式与差异检查通过；非作者审查0阻断。
- 捕获监听和三个原生浏览器合成夹具没有复现原console错误。首次失败仅为额外的信号时点断言，不能作为原故障红测。失败证据保留，不宣称原生浏览器修复已验证。

实际新版本只读导航及完整发布验收仍待执行。a13继续运行旧冻结产物；没有重放已成功保存，未推送或正式部署。该修复不改变用户操作步骤，中文手册内容不需新增操作。
