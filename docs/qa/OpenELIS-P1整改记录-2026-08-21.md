# OpenELIS P1 整改记录 — 2026-08-21

## 1. 产品整改目标

本轮不以“页面能打开”作为完成标准，而以检验业务可连续执行、状态可解释、数据不被静默污染为目标。P1 整改遵循四条产品原则：

1. 患者身份、订单、样本和结果只有一个可信状态来源；
2. 未配置、校验失败或保存失败时必须明确阻止流程，禁止显示假成功；
3. 同一操作重复执行必须安全，客户端结果必须与数据库提交结果一致；
4. 本地 HTTP 调试环境保持 HTTP，生产 HTTPS 能力不被破坏。

- 已显式标记安全的聚合报告目前只要求 `ROLE_REPORTS`，尚未按实验室单元过滤；HIV 等小样本计数还需确定并实现最小展示阈值，避免重识别；
- SSO 登录科室仍依赖展示名称和 `-` 分隔解析，重名或名称含连字符时不稳定，应改为稳定科室 ID；批量导出检查目前嵌套在结果范围能力内，当前调用安全，但后续应改成独立组合策略防止新增实现误用；
- 个别 `UserService` 空角色映射输入仍可能返回 500，属于可靠性而非越权问题；控制器测试还应增加“拒绝时从未初始化/运行报告”的断言及真实会话集成测试；
- 统计报告空条件 500 已修复并完成 PDF/Chrome 复验；非 COVID 报告仍需补齐 DST、无界日期和大数据量 N+1 等可靠性/性能边界；

## 6. 交付判定规则

- 只有代码完成但未部署复验：状态为“已修复，待复验”；
- 页面成功但数据库状态不一致：仍判定失败；
- 数据库已提交但接口返回失败：仍判定失败；
- QA 未配置、必要主数据缺失或未选择检测项目：必须阻止并给出可执行提示；
- 本轮所有 P1 通过后，环境才可从“开发演示”升级为“业务试用候选”；正式生产交付仍需角色权限、报告版式、备份恢复、性能容量和外部接口联调验收。
