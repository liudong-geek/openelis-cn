# B-01 / E-01：修改申请的必填申请日期

日期：2026-10-16。状态：已集成到隔离候选，局部验证通过；完整构建、真实浏览器验收和正式部署待完成。

## 实际故障与原因

a14 原修改申请第14场景 POST `/rest/SampleEdit` 返回400。被动观察保存同一 requestId 的真实载荷和回执；错误精确为 `sampleOrderItems.requestDate`、`OptionalNotBlank`、`Cannot be blank`。私有载荷不放入仓库。

原隔离种子没有申请日期观察记录，编辑 GET 正确返回其缺值，前端也没有删掉日期。实际后端按已有 `FormFields.Field.SampleEntryUseRequestDate` 判定必填，但原编辑 schema 未验证该字段，导致用户到保存时才收到含糊错误。早前离线校验遗漏 `setFieldForm`，使用默认不启用字段的配置，不能据此否定实际400。

## 修复边界

- 编辑表单增加只读 `requestDateRequired` 元数据，直接使用后台现有 FormFields 配置。客户端不能覆盖该标志，原后台必填与过去日期校验不变。
- 前端按该标志提示必填并在保存前定位申请日期。对服务器返回的同一字段、同一校验码显示中文字段提示，失败保留草稿。
- 异步解析错误回执后再次核对挂载状态与申请身份；旧申请的迟到错误不能写进另一申请。
- 历史日期保持原值；缺值不自动替换为当天或接收日期。不修改种子、编号、患者资料、角色、权限、保存次数与业务事务。

## 原19场景助手适配

原 `modifyOrder.cy.js` 19场景保持。`Order.json` 仅增 `modifyRequestDateISO=2024-01-02`，它是明确的合成申请事实，不是患者历史日期，也不取当前或接收日期。仅实际编辑GET同时满足 `requestDateRequired === true` 且申请日期为空时，通过真实输入控件录入；按实际placeholder转换显示顺序。已有日期保留。

日期填写使用 Escape＋blur 关闭共享真实日历，不使用可能触发表单提交的 Enter。独立共享Carbon/Flatpickr离线载体已验证该序列保值、关闭日历及显式保存前0POST；该证据不替代真实浏览器几何与页面验收。修改申请使用div/fieldset，未新增form。
