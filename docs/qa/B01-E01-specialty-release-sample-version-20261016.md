# B-01 / E-01：专科签发使用申请当前版本

## 问题与范围

兼容版 a14 病理签发发生 Sample 乐观锁冲突，返回 HTTP 500。失败后只读核对显示病例仍待病理医生处理，检验分析未签发，结果未落库。主版专科继续关闭。

结果持久化首次创建结果时，将申请状态更新为“检验中”。审计服务移出原实体，DAO merge 和 flush 产生带新版本的实体。专科服务随后复制原申请对象并更新为完成，使用了旧版本。

病理、免疫组化、细胞学三个签发入口在原有全部分析终态检查通过后，重新取得同事务中的当前申请，再建立既有审计用副本完成更新。权限、责任人、签发集合、未完成分析阻断、事务、历史和全局乐观锁规则保持。

## 局部验证

原两份签发服务测试保留 5 项，新增 6 项。持久化边界模拟审计更新返回不同实体并推进版本：旧产品代码 11 项中 8 通过、3 失败，三个专科均因旧版本失败；每个专科的未完成申请场景均保留不关闭行为。

候选通过两份签发服务及原权限、责任人、转免疫组化、控制器授权等共 8 文件 59 项。新增测试核对当前版本、当前字段、独立审计副本、操作人、完成状态和未完成申请零关闭写入。格式检查通过；产品文件附带格式器的换行及导入顺序整理。

## 验证边界

本轮局部测试调用实际三个签发方法，数据库持久化边界使用模拟对象；没有将其称为真实 Hibernate 或临床验收。已有 SpecialtyReleaseAuditIntegrationTest 使用数据库和真实审计服务，原场景每个申请只更新一次，没有覆盖本次同事务两次更新。

本次没有重放 a14 的保存或签发，也没有修改其业务数据。集成后须重建后端，使用新鲜隔离数据完成原兼容验收；本次局部通过不替代原 349、主版 335、关闭检查和补充验收。
