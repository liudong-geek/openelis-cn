# B-01 / E-01：修改申请保留所选医生身份

## 范围与状态

本候选仅调整 `SampleOrderService.createPersonProviderArtifacts` 的已有医生解析顺序。未修改前端、Cypress 助手、19 个既有修改申请场景、权限、事务和接口。根已集成并复编同 7 项通过；尚未部署，完整真实保存回归待下一份全新验收环境运行。此前 a15 已成功保存的申请不得重复提交。

## 实际故障与证据

- a15 原后续 142 场景中的修改申请第 14 项：保存 POST 已返回成功，提交字段的医生 / 人员 ID 断言通过，独立保存查询在 `persisted providerId` 断言失败，实际为 `5`，原所选为 `9000001`。
- 根执行的单次只读查回确认：保存后的医生 `5` 关联人员 `9200108`，原医生 `9000001` 仍关联人员 `9000001`，双方姓名相同。查回业务 POST 为 0，运行版本一致。证据位于外部 `a15-order-provider-diagnosis/actual-readback/verification.json` 及其绑定的私有记录。
- 未取得保存前医生为空的直接响应，不把种子语义或离线复现写作现场已核实的原始字段。

## 假设与实际反馈

| 假设                                         | 证据与结论                                                                                                                                              |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 前端没有提交所选医生身份                     | 原助手先验证请求医生 / 人员 ID 后才独立查回；该假设与本次断言顺序不符。                                                                                 |
| 查回把同一人员的另一医生 ID 当作选中医生     | 只读查询确认新、旧人员 ID 也不同，不能仅以同名 / 同一人员多映射解释。                                                                                   |
| 旧申请缺医生时，保存构造器忽略已选医生并新建 | 实际源码 `namesDiffer(null, order)` 返回 true，直接跳过已选人员查询。离线调用真实构造器稳定重现，修复后通过。该反馈证明分支缺陷，不补造现场保存前响应。 |
| 明确改名时需要保留原有新建规则               | 同一真实方法回归覆盖已有医生改名、切换医生后改名与手工医生；修复仍不把新姓名写回原医生姓名字段。                                                        |

## 修复

先按提交的 `providerPersonId` 解析已有医生，再比较该医生的姓名与提交姓名。姓名未改时直接保留已有 Provider / Person 身份；明确改名或手工填写时继续使用原有的新建路径。申请的 requester 关联和审计用户赋值路径保持原样。

本改动没有新增 `providerId` / `providerPersonId` 的交叉校验。原保存路径仍会调用现有 Person / Provider 的 save 与审计，因此这里的主数据保护仅指不改写原医生的姓名、电话等业务字段，不能称为零主表保存或零审计写入。

## 已执行验证

外部一次性 Java 载体直接编译实际 `SampleOrderService`、`RequesterService`，调用真实医生持久化产物构造方法，依赖服务使用现有 Mockito / Spring 测试工具。它不调用 Hibernate、不访问数据库、不发送 HTTP，不能替代完整保存验收。

- 初次载体编译失败为非静态内部类实例化写法，记录保留于 `baseline-run/compile.log`，不计产品红测。
- `baseline-v2-run`：7 项，4 通过 / 3 失败。失败包括旧申请无医生时选已有医生、同类空姓名字段、切换医生后明确改名。
- `candidate-run`：同 7 项全部通过。还覆盖原医生不变、从另一医生切换、手工医生，以及关联对象与审计用户保留。
- 载体通过独立进程执行，跳过无关构造器初始化。因 RequesterService 有静态缓存，该临时测试不进入仓库或共用 JVM 的完整测试套件。产品已有的 Cypress 19 场景中本次失败场景继续作为真实持久化回归，不删除、不放宽身份断言。
