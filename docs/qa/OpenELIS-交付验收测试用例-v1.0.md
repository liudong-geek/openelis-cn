# OpenELIS 交付验收测试用例 v1.0

## 1. 测试目标

验证当前本地 OpenELIS 是否达到“业务人员可理解、核心流程可完成、关键数据可追溯、异常可恢复”的交付标准。测试同时覆盖：

- 界面可用性与交互反馈；
- 患者档案、检验申请、标本、检验、审核签发、报告的业务闭环；
- 权限、必填校验、重复提交、异常恢复等负向场景；
- HTTP 接口、后台日志、数据库状态和 FHIR/外部对接健康度；
- 中文化、可访问性、性能和浏览器兼容性。

## 2. 执行规则

- 环境：本地 HTTP 调试环境 `http://127.0.0.1:18080`。
- 测试数据前缀：`QA-20260821-`，不得使用真实患者信息。
- 浏览器主验收：Google Chrome 桌面版；Firefox/Safari 作为兼容性补测。
- P0：核心业务或数据安全阻断；P1：主要功能错误或明显业务风险；P2：可用性、翻译、视觉或低频场景问题。
- 核心链路执行顺序：患者建档 → 检验申请 → 标本采集/签收 → 贴签/上架 → 结果录入 → 结果审核 → 报告签发。
- 涉及保存的用例必须检查三项证据：页面成功反馈、刷新后仍存在、后台无新增 5xx/严重异常。
- 交付门槛：P0 全通过；P1 通过率不低于 95% 且无核心链路阻断；P2 必须有明确修复计划。

每条用例记录：执行时间、执行人、环境版本、测试数据标识、实际结果、状态（通过/失败/阻塞/未执行）、证据、缺陷编号。失败项必须包含可复现步骤和后台证据，不接受只写“不能用”。
